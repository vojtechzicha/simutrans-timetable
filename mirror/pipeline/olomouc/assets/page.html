A set is what runs one course: on weekdays two 15-metre cars coupled (the Inekon 01 Trio runs solo). Every set on 18 Sep was a pair. The counts leave out sets logged beyond a Simutrans line's need at 16:00 (marked “not needed”; none on 18 Sep). The “Trams” box on each line card uses the same rule.

Pak128 objects

The one place with full object names from the custom Czech pak128 set (VZ-DPOlomouc-tram.pak). Elsewhere each vehicle shows only the core of the name, the last part after the livery, with the livery added where the pak has more than one for that type. “≈” marks a substitute; the reason is in this table. Articulated trams are several objects that the depot builds as one vehicle, in the order shown. Length is in carunits (16 = one tile).

How this was built

  • Day. Fri 25 Sep has 7 sets recorded and the rest of that week has fewer. Fri 18 Sep has 26 sets covering every line, which matches what the timetable needs at 16:00 by round trip (shown on each line card). The DPMO timetable of 18 Sep is identical to the one valid on 27–29 Sep, so the network is the current state.
  • Vehicles. seznam-autobusu.cz, vypravenost/mhd-ol/vypis?datum=2026-09-18&linka=N. Every record gives course and set, and no swaps or split courses were recorded that day. Types, paint and depot come from the DPMO fleet register on the same site. Car 156 is listed as withdrawn on 18 Sep 2026.
  • Shared pool 3 + 5. Line 5 has no records of its own; the 6 line-3 courses match the 6 sets the two lines need together (3: 4, 5: 2). The two lines run at different intervals, so in Simutrans they are two lines drawing on one pool of bidirectional sets. Which course runs which line is a choice. U Kapličky is a stub and keeps the timetable minute.
  • Designed trams. None needed: every line's recorded sets cover its round-trip need. Had a line fallen short, the missing sets would be real cars from that line's own history, checked as not out anywhere that day and marked “designed, not recorded” with the date they last ran the line.
  • Not needed (user, 29 Sep 2026). Where more sets are logged on a Simutrans line (a line, or line 3 or 5 of the 3 + 5 pool) than it needs at 16:00, exactly the need is counted. One set of every type on the line is kept first (most frequent type first), then recorded before designed, then the lowest course numbers. The rest are marked “not needed”, dimmed, and left out of the counts, depots and pak totals. On 18 Sep every line had exactly its need, so no set is marked.
  • Simutrans schedule. Values for the Scheduling tab of your fork (calendar on). The fit follows the shared rule in pipeline/README.md: the longest exact run of one Departure every / Offset / Also at pattern (at most 8 slots, whole minutes) around the 15:30–16:30 core, clipped to the pattern's first and last departure. Loop termini are set 1 minute early: Fibichova, Nová Ulice, Neředín and Pavlovičky are loops, so Offset and Also at are the timetable minute minus 1 (modulo the interval), with the real minute printed under each. U Kapličky keeps the timetable minute. Trips into the depot at Náměstí Hrdinů are not modelled.
  • Pak128 objects. VZ-DPOlomouc-tram.pak, pak128 main %%PAK_COMMIT%%, confirmed with the pak128 session. One real car is one object. Bidirectional pairs are the object plus its “-reverse” twin (EVO1o + EVO1o-reverse, VarioLF_plus_o + VarioLF_plus_o-reverse). VarioLFR.S, VarioLFR.E and VarioLF.E have the same body at this scale and are all the VarioLF object, an exact match. Advert wraps are ignored.
  • Timetable. DPMO GTFS (dpmo.cz/doc/dpmo-olomouc-cz.zip, version %%GTFS_RAW%%), service date %%SERVICE_DATE%%. Alighting at Hlavní nádraží and boarding at Fibichova are one loop, merged under Fibichova.
  • Rebuilding. This page is generated by pipeline/olomouc (python scripts/run.py --state 2026-09-27) from the raw data stored there; see pipeline/olomouc/README.md.
