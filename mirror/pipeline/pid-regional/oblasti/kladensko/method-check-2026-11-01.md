## Script problems

- `pid-regional/scripts/run_oblast.py` line 40 had a literal newline inside an f-string (`print(f"<newline>coverage: …`), a
  SyntaxError on Python 3.14 from about 05:20 on 2 Nov. I ran it through an in-memory wrapper in my scratchpad without touching
  the file; the coordinator has since fixed it and every later run used the script directly. The scratchpad root is shared
  by all designers: my first wrapper there was overwritten by another designer's version of the same in-memory fix, which I
  read and then used once for the `--draft` run. Everything else ran from my own files in the `kladensko` subfolder, and the
  final `lines.json` is byte-identical to my generator's output.
- `05_schedule.py` knot check: the model's passing time at each core point uses the **median of all the line's trips** over that
  stretch, not the leg's own path or its `knot_rt` / `rt`. Legs whose slot trips take a slower variant (588 via Líský, 630 via
  Valdek, 365 via Družec, 555 from Újezd) therefore show 4 – 10 min "deviations" on the card that the game line does not have.
  A fix would take the offsets from the trips of the leg's `stops_via` path, or shift them by `knot_rt − median`.
- `05_schedule.py` minimum wait: the "less where the slots chain closer" rule also fires where the chain is only a coincidence of
  the repeating pattern (300 Kladno: 17:44 arrival → 17:45 slot, no such real turn), which lowered the need from 3 to 2; I set
  `lay` 3 by hand there. A real turn could be told from a coincidence by checking a real trip pair at those minutes.
- `06_render.py` owner checks: the first field is split on spaces and used as a line anchor; a sheet-wide check therefore needs a
  line number first (I used "306 587 708" for the near-stops check).
